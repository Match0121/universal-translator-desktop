Title: 我做了个把文件拖进去就自动翻译的桌面工具（不止游戏）

## 从一个乱码的剧本开始

某个周末，我翻出一个存了很久的日文视觉小说，准备认真玩一下。打开游戏目录，熟悉的挫败感又来了：剧本是 .ks 文件，Shift-JIS 编码，记事本打开全是乱码；更大的麻烦是剧本装在 data.xp3 资源包里，想翻译得先找解包工具、再转码、再逐句复制到翻译网站。来回折腾半小时，游戏一局没玩上。

那一刻我在想：翻译文本这件事，本不该这么麻烦。于是有了万能翻译站（Universal Translator），一个 Windows 桌面工具。做的时候我发现，这个思路可以不止于游戏：不用在文件管理器与多种翻译软件之间挣扎，不管是文件、游戏还是图片，把内容拖进窗口，识别、提取、翻译、替换，一个平台解决所有烦恼。这是它的定位，也是我继续做下去的方向。

## 它现在做了什么

当前文本文件与游戏文本的完整链路已经实现：

1. 拖入文件或整个游戏文件夹，自动扫描文本、识别游戏引擎（吉里吉里、Ren'Py 等）
2. 自动检测文件编码。日文游戏剧本大多是 Shift-JIS，主流工具按 UTF-8 读就是乱码；这里通过 BOM 识别、UTF-8 严格校验、假名分布投票三层判断，日文剧本无需手动转码
3. 按格式提取文本单元，批量翻译（可切 MyMemory、百度、DeepL，或接本地 LLM）
4. 按文件查看对照译文，导出时保持原编码写回

## 最麻烦的一步：xp3 资源包

吉里吉里（KiriKiri）引擎是日式视觉小说的主流引擎之一，它把剧本、图片、语音都打包进 .xp3 文件。文本扫描工具看不到包里的内容，这也是很多"翻译工具"覆盖不到的地方。

我参照 krkrz 开源 SDK 的格式规范实现了 xp3 的解包与封包：扫描到资源包后一键解包，包内剧本进入同一套翻译流程，翻译完成后按原格式重新封包。实测对小厂无加密的 xp3 完整可用；加密包（带 hook 插件的）会明确提示暂不支持，不硬解。

过程中踩了几个格式坑：xp3 的 magic 是 7 字节而非 8、文件名是带 2 字节 null 终止符的 UTF-16LE、段偏移是相对文件头的绝对定位。每个坑都靠对着二进制逐字节比对才排掉。

## 设计上的取舍

提取层用的是行级单元模型：每个文本单元记录行号、行内出现次序、原文和原始形态，提取与写回共用同一套定位。好处是天然支持原文/对照/译文三态切换，导出时能精确还原原文件结构。

编码检测里的一个细节：日文纯汉字词（比如"回復薬"）没有假名，容易被误判成"已是中文"而跳过。这个规则只在 GBK（中文游戏）文件上启用，日文文件的纯汉字词保留提取。

界面请设计师做了两版方案，最后实装的是"高级简约"风格：暖灰纸感浅色 + 暖石墨深色双主题，细线 SVG 图标。产品形态是 PyInstaller 打包的单文件 exe，双击即用，无需安装 Python。
